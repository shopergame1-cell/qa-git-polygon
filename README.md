# QA Git Polygon

Публічний полігон для практики складних Git-сценаріїв (курс QA Mentorship).
Кожен сценарій — окремa тека з двома скриптами:

- `setup.sh` — готує «зламаний» стан у твоєму форку (створює гілки, коміти, конфлікти);
- `check.sh` — перевіряє, чи ти розвʼязав сценарій правильно (те саме робить GitHub Actions).

## Як користуватись

```bash
# 1. Форкни цей репозиторій (Fork -> Create fork)
git clone https://github.com/<твій-логін>/qa-git-polygon.git
cd qa-git-polygon

# 2. Обери сценарій
bash scenarios/01-merge-conflict/setup.sh

# 3. Розвʼяжи його руками в терміналі (нічого не підглядай у check.sh — сенс у практиці)
# ...

# 4. Перевір себе локально
bash scenarios/01-merge-conflict/check.sh

# 5. Запуш у свій форк
git push origin main --force-with-lease

# 6. Скопіюй посилання на зелений прогін Actions і прикріпи його як артефакт у курсі
```

## Сценарії

| # | Сценарій | Що тренує |
|---|---|---|
| 01 | merge-conflict | конфлікт при merge у 2 файлах, збереження обох намірів |
| 02 | rebase-squash | інтерактивний rebase: squash трьох комітів і reword |
| 03 | reflog-recovery | відновлення втраченого коміту після hard reset |
| 04 | rebase-conflict | конфлікт під час rebase і лінійна історія |
